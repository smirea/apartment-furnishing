# Workflow

- **Hooks install with `bun install`.** Bun skips dependency lifecycle scripts, so lefthook's own installer never runs; the root `postinstall` runs `lefthook install` when `.git` is present.
- **Hooks run the checks for the stacks a change touches.** Pre-commit runs `agent-t3-worktree check --heal` when that command exists, then one parallel group: `oxlint --fix` on the staged scripts, `bun run typecheck` when a script or JSON file is staged, and the whole test suite, which takes milliseconds, when a script is staged. The test job unsets git's hook variables first, so a test that runs git in a temp directory can't act on this repository. Formatting is not enforced. Nothing runs at pre-push: it would rerun what pre-commit just ran.
- **CI runs each check as its own job.** `lint:ci`, `typecheck`, `test` and `build` run in parallel on every change, with no change detection in front, since a detection job cost more than it saved. They time out at 5 minutes. The Worker deploy needs all four and runs only on pushes to master. `app-ios` has no CI job.
- **The type check covers the whole repo.** `bun run typecheck` runs `bun check` at the root for `packages/shared` and `scripts/`, then each app's own check.
- **Git hooks are never skipped.** A Claude Code hook in `.claude/settings.json` blocks `--no-verify` and lefthook overrides. A failing hook gets its cause fixed; a flaky test is a bad test.
- **Friction gets fixed or filed.** Development speed is a goal in itself. An agent that hits a manual step, a repeated prompt, a slow command, or a flaky tool fixes it in the same thread when the fix is small, and otherwise opens a GitHub issue with its findings and a proposed fix.
- **Environments start on the default path.** The common case is someone using the app with everything allowed and real-looking data, so dev environments grant every permission and seed data up front. Testing a denied, limited, or empty state is the exception: the agent revokes the permission or clears the data for that test.
